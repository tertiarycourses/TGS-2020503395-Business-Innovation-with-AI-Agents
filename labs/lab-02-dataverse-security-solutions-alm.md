# Lab 2 - Dataverse Security, Solutions, Environment Variables, and ALM

## Objective

Configure or design Dataverse security, solutions, dependencies, environment variables, solution layers, and ALM practices.

## Scenario

Contoso developers currently make changes directly in production. The team needs a managed solution lifecycle across development, test, and production.

## Tasks

### Step 1 - Design environment strategy

Create a table:

| Environment | Purpose | Solution type | Access |
|-------------|---------|---------------|--------|

Include development, test, and production.

### Step 2 - Configure solution structure

Plan solution components:

- Tables
- Columns
- Model-driven app
- Canvas app
- Cloud flows
- Plug-in assembly
- Custom connector
- Environment variables
- Connection references

### Step 3 - Define security roles

Create a role matrix:

| Role | Table privileges | App access | Notes |
|------|------------------|------------|-------|

Include service manager, technician, integration user, and system customizer.

### Step 4 - Plan environment variables

Define:

- API base URL
- Azure Function URL
- Feature flag
- Support email
- Key Vault secret reference concept

### Step 5 - Document ALM controls

Write controls for:

- Managed and unmanaged solutions
- Solution dependencies
- Solution layers
- Version numbering
- Export/import process
- Rollback planning

## Deliverable

Submit environment strategy, solution component list, security role matrix, environment variable plan, and ALM checklist.

## Checkpoint questions

1. Why should production use managed solutions?
2. What are environment variables used for?
3. How can solution layers affect troubleshooting?
